# 第7课：AI 数据查询助手（综合 Demo）

## 这节课做什么

整合前六课的核心技能，做一个完整的 AI 功能：

```
用户用自然语言提问
      ↓
Agent 先调 get_schema() 了解表结构
      ↓
Agent 生成 SQL 并调 execute_sql() 执行
      ↓
Agent 用自然语言解释查询结果
```

这是面试里"你做过哪些 AI 相关项目"的标准答案素材。

---

## 系统架构

```
用户输入
  ↓
ReAct Agent（第6课）
  ├── 工具1: get_schema()   → 返回表结构（让 LLM 知道有哪些字段）
  └── 工具2: execute_sql()  → 执行 SELECT 语句，返回结果
  ↓
自然语言回答 + 数据洞察
```

**数据库**：SQLite（Python 内置，无需安装）

**安全设计**：`execute_sql` 只允许 SELECT，拒绝 INSERT/UPDATE/DELETE/DROP。

---

## 两个关键工具

### get_schema

```python
@tool
def get_schema() -> str:
    """获取数据库所有表的字段结构，生成 SQL 前必须先调用此工具"""
    return """
products(id, name, category, price)
customers(id, name, city, join_date)
orders(id, customer_id, product_id, quantity, total_price, order_date)
"""
```

为什么必须先调这个工具？LLM 不知道数据库里有哪些表和字段，直接让它写 SQL 会写出不存在的字段名。让它先"读手册"再写 SQL，准确率大幅提升。

### execute_sql

```python
@tool
def execute_sql(query: str) -> str:
    """执行 SQL 查询并返回结果，只允许 SELECT 语句"""
    if not query.strip().upper().startswith("SELECT"):
        return "错误：只允许 SELECT 查询"
    # 连接 SQLite，执行，格式化结果返回
    ...
```

返回值格式化成人类可读的表格字符串，让 LLM 能理解并解释。

## 面试技术要点

### 为什么用 Agent 而不是直接让 LLM 写 SQL？

直接问 LLM "写一个查销售额最高产品的 SQL"，LLM 可能会：
- 猜测不存在的字段名
- 假设错误的表关系

用 Agent + get_schema 工具，LLM 先"看"了真实的表结构，再写 SQL，准确率高很多。而且如果 SQL 执行出错，Agent 能看到错误信息并自动修正。

### 为什么 execute_sql 只允许 SELECT？

防止 LLM 生成误操作：如果用户问"删掉所有订单"，没有保护的 Agent 可能真的执行 DELETE。限制为只读 SELECT，把写操作的风险完全隔离。

### 生产中还需要什么？

- **连接池**：SQLite 单连接，生产用 PostgreSQL + 连接池
- **参数化查询**：防止 SQL 注入（用 `?` 占位而非字符串拼接）
- **结果长度限制**：查询返回大量行时截断，避免超出 LLM context
- **权限控制**：不同用户只能查自己部门的数据

## 动手实验

1. 给数据库加一张新表 `returns`（退货记录：id, order_id, reason, return_date），更新 `get_schema` 返回值，然后问 Agent "退货最多的原因是什么？"
2. 故意问 "删掉所有产品"，验证 execute_sql 的保护是否生效
3. 把 `max_iterations` 从 8 改成 3，问一个复杂问题（如"购买过显示器且在北京的客户名单"），观察 Agent 步数受限时的表现
4. 在 `execute_sql` 里加行数限制（`c.fetchmany(10)` 替换 `c.fetchall()`），测试大结果集时 Agent 能否根据截断后的结果给出合理答案

## 面试怎么说

> "我做了一个 AI 数据查询助手，用户用自然语言提问，系统自动生成 SQL 查数据库，然后用自然语言解释结果。
>
> 核心是两个工具：一个 get_schema 让 LLM 了解表结构，一个 execute_sql 执行查询。用 ReAct Agent 串起来，LLM 会自主决定先看表结构、再写 SQL、再解释结果。
>
> 安全上做了限制：只允许 SELECT，不允许写操作，SQL 异常会返回错误让 Agent 自动修正 SQL 重试。
>
> 这个方案的优势是零配置（SQLite 内置）、可扩展（换 PostgreSQL 只改连接那行），缺点是复杂查询可能需要多轮工具调用，成本比直接生成 SQL 高。"
