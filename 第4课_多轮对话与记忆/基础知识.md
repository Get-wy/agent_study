# 第4课：多轮对话与记忆

## 这节课解决什么问题

LLM 本质上是**无状态**的——每次调用都是全新的，它不记得上一次你说了什么。

```
你：我叫小明
AI：你好，小明！

你：我叫什么？        ← 新的一次 API 调用，LLM 完全不知道之前的对话
AI：抱歉，我不知道你叫什么
```

要实现"上下文记忆"，必须**每次把历史消息一起传给 LLM**。记忆不是 LLM 的功能，是你的应用层维护的。

---

## 底层机制：消息列表

LLM 的"记忆"就是一个消息数组：

```python
messages = [
    HumanMessage("我叫小明"),
    AIMessage("你好，小明！"),
    HumanMessage("我叫什么？"),   # ← 第三轮时发送前三条
]
response = llm.invoke(messages)  # 传入完整历史
```

每一轮对话：
1. 把用户新消息 append 到列表
2. 把整个列表发给 LLM
3. 把 AI 回复 append 到列表
4. 下一轮重复

---

## Token 成本会线性增长

这是全量记忆的核心问题，必须理解。

```
第 1 轮：发送 50 tokens
第 2 轮：发送 120 tokens（含第1轮历史）
第 3 轮：发送 200 tokens（含前2轮历史）
第 N 轮：发送 N * 平均每轮 tokens
```

假设每轮平均 100 tokens，对话 50 轮：

| 方案 | 第50轮发送 tokens | 累计费用倍数 |
|---|---|---|
| 全量记忆 | 5000 tokens | 25× |
| 窗口记忆（保留5轮） | 500 tokens | 固定 |
| 摘要记忆 | 摘要100 + 近期300 = 400 tokens | 近似固定 |

长对话用全量记忆，费用会爆炸，还会超出模型的 context window（qwen-plus 是 32k tokens）。

---

## 三种记忆策略

### 策略 1：全量记忆（Buffer Memory）

```python
messages = []

def chat(user_input: str):
    messages.append(HumanMessage(user_input))
    response = llm.invoke(messages)
    messages.append(AIMessage(response.content))
    return response.content
```

**优点**：实现最简单，记忆完整不丢信息  
**缺点**：token 线性增长，长对话必然超限  
**适合**：短任务、单次对话、调试阶段

---

### 策略 2：窗口记忆（Window Memory）

只保留最近 N 轮，丢弃更早的历史。

```python
history = []  # [(human, ai), ...]

def chat(user_input: str, max_turns: int = 5):
    recent = history[-max_turns:]          # 只取最近 N 轮
    messages = []
    for human, ai in recent:
        messages.append(HumanMessage(human))
        messages.append(AIMessage(ai))
    messages.append(HumanMessage(user_input))

    response = llm.invoke(messages)
    history.append((user_input, response.content))
    return response.content
```

**优点**：token 固定，永远不会超限  
**缺点**：早期信息丢失，用户自我介绍5轮后AI就忘了  
**适合**：闲聊机器人、短上下文场景

**关键问题**：`max_turns` 怎么定？太小丢信息，太大省不了 token。经验值 5-10 轮。

---

### 策略 3：摘要记忆（Summary Memory）

近期消息保留原文，超出阈值就让 LLM 压缩成摘要，摘要作为 `SystemMessage` 传入。

```python
summary = ""
recent = []
COMPRESS_THRESHOLD = 6  # 超过6条消息就压缩

def compress(summary: str, messages: list) -> str:
    history_text = "\n".join(
        f"{'用户' if isinstance(m, HumanMessage) else 'AI'}: {m.content}"
        for m in messages
    )
    prompt = (
        f"将以下对话压缩成100字以内的摘要，保留所有关键信息。\n"
        f"已有摘要：{summary or '无'}\n"
        f"新增对话：\n{history_text}\n"
        f"压缩摘要："
    )
    return llm.invoke([HumanMessage(prompt)]).content


def chat(user_input: str):
    messages = []
    if summary:
        messages.append(SystemMessage(f"之前对话摘要：\n{summary}"))
    messages.extend(recent)
    messages.append(HumanMessage(user_input))

    response = llm.invoke(messages)
    ai_reply = response.content

    recent.append(HumanMessage(user_input))
    recent.append(AIMessage(ai_reply))

    if len(recent) >= COMPRESS_THRESHOLD:
        summary = compress(summary, recent)
        recent.clear()

    return ai_reply
```

**优点**：长期信息不完全丢失，token 成本近似固定  
**缺点**：压缩有信息损耗；压缩本身需要额外调用 LLM  
**适合**：客服机器人、长期助手、需要记住用户身份信息的场景

---

## 三种策略对比

| | 全量记忆 | 窗口记忆 | 摘要记忆 |
|---|---|---|---|
| 实现难度 | ⭐ | ⭐⭐ | ⭐⭐⭐ |
| token 成本 | 线性增长 | 固定 | 近似固定 |
| 信息完整性 | 100% | 只保留近期 | 大致保留（有损） |
| 超出 context 风险 | 高 | 无 | 极低 |
| 额外 LLM 调用 | 无 | 无 | 有（压缩时） |

**实际项目选型建议**：

- 短任务（写代码、改文案）→ **全量记忆**，任务结束清空
- 多轮闲聊、客服 → **窗口记忆**，max_turns = 8
- 长期助手、记住用户身份 → **摘要记忆**

## 消息类型

LangChain 有四种消息类型，对应 LLM 的不同"角色"：

```python
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage, ToolMessage

SystemMessage("你是一个专业的前端工程师助手")  # 系统提示，设定 AI 身份
HumanMessage("帮我写一个 useEffect 的示例")     # 用户消息
AIMessage("好的，以下是示例：...")               # AI 回复
ToolMessage("查询结果：...", tool_call_id="...")  # 工具调用结果（第2课用过）
```

`SystemMessage` 通常放在消息列表第一位，用来设定 AI 的人设和行为规范。

```python
messages = [
    SystemMessage("你是一个专业的前端面试辅导老师，回答要简洁有针对性"),
    HumanMessage("什么是闭包？"),
    AIMessage("..."),
    HumanMessage("再举个实际例子"),
]
```

```
  [触发压缩：4 条消息 → 摘要]

用户: 根据你对我的了解，给我一点学习建议
AI: 小明，作为前端工程师学 AI Agent...    ← 基于摘要仍然记得之前的信息
```

## 持久化：存到数据库

上面的实现都在内存里，程序重启就丢了。实际产品需要持久化：

```python
import json

# 保存会话到文件（生产用数据库）
def save_history(session_id: str, history: list):
    data = [
        {"role": "human" if isinstance(m, HumanMessage) else "ai", "content": m.content}
        for m in history
    ]
    with open(f"{session_id}.json", "w") as f:
        json.dump(data, f, ensure_ascii=False)


# 加载会话
def load_history(session_id: str) -> list:
    try:
        with open(f"{session_id}.json") as f:
            data = json.load(f)
        return [
            HumanMessage(d["content"]) if d["role"] == "human" else AIMessage(d["content"])
            for d in data
        ]
    except FileNotFoundError:
        return []
```

生产中通常用 Redis（短期）或 PostgreSQL（长期）存储，key 是 `session_id` 或 `user_id`。

## 面试怎么说

> "LLM 本身是无状态的，每次调用都是独立的。多轮对话的实现原理是：每次请求都把历史消息列表一起发给 LLM，应用层负责维护这个列表。
>
> 问题是 token 会线性增长。短对话可以全量保留；长对话有两种处理方式——窗口记忆只保留最近 N 轮（简单但会丢失早期信息），摘要记忆是把早期对话让 LLM 压缩成摘要继续传入（有损但节省 token）。
>
> 实际项目里还要考虑持久化：session 粒度存到 Redis 或数据库，用 session_id 区分不同用户的会话。"
