# 第2课：Function Calling（工具调用）

## 这节课解决什么问题

第1课的 RAG，AI 只能基于你给的文档回答。

但实际业务里经常需要：

- "查一下今天的订单量" → 去数据库查，不是靠文档
- "帮我创建一个工单" → 调接口，不是靠生成文字
- "现在几点" → 模型不知道，要调系统

**Function Calling 就是：让 LLM 决定调哪个函数、传什么参数，你来执行，结果再还给 LLM。**

---

## 执行流程

```
用户问题
  → LLM 判断：需要调函数，参数是 xxx
  → 你的代码执行函数
  → 把执行结果还给 LLM
  → LLM 基于结果组织自然语言回答
```

LLM 不直接运行代码，它只负责"决策"。

---

## Demo 代码

模拟一个真实场景：AI 助手查订单、查用户信息。

```python
import os
import json
from openai import OpenAI

client = OpenAI(
    api_key=os.getenv("aliQwen-api"),
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)

# ① 定义你的"工具"函数（模拟数据库查询）
def get_order_count(date: str) -> dict:
    """模拟查询某天的订单量"""
    fake_data = {
        "2024-01-15": 128,
        "2024-01-16": 97,
        "2024-01-17": 215,
    }
    count = fake_data.get(date, 0)
    return {"date": date, "count": count}


def get_user_info(user_id: str) -> dict:
    """模拟查询用户信息"""
    fake_users = {
        "U001": {"name": "张三", "level": "VIP", "orders": 42},
        "U002": {"name": "李四", "level": "普通", "orders": 3},
    }
    return fake_users.get(user_id, {"error": "用户不存在"})


# ② 告诉 LLM 有哪些工具可以用（JSON Schema 格式）
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_order_count",
            "description": "查询指定日期的订单量",
            "parameters": {
                "type": "object",
                "properties": {
                    "date": {
                        "type": "string",
                        "description": "日期，格式 YYYY-MM-DD",
                    }
                },
                "required": ["date"],
            },
        },
    },
    {
        "type": "function",
        "function": {
            "name": "get_user_info",
            "description": "查询用户的基本信息和订单历史",
            "parameters": {
                "type": "object",
                "properties": {
                    "user_id": {
                        "type": "string",
                        "description": "用户ID，格式 U + 数字",
                    }
                },
                "required": ["user_id"],
            },
        },
    },
]

# ③ 函数路由表：LLM 说调哪个，就执行哪个
FUNCTION_MAP = {
    "get_order_count": get_order_count,
    "get_user_info": get_user_info,
}


def chat_with_tools(user_message: str):
    print(f"\n用户: {user_message}")
    messages = [{"role": "user", "content": user_message}]

    # 第一次调用：LLM 决定要不要调函数
    response = client.chat.completions.create(
        model="qwen-plus",
        messages=messages,
        tools=tools,
        tool_choice="auto",  # 让模型自己决定
    )

    msg = response.choices[0].message

    # ④ 判断 LLM 的决策
    if msg.tool_calls:
        print(f"\n[LLM 决定调用工具]")

        # 把 LLM 的决策加入消息历史
        messages.append(msg)

        # ⑤ 执行 LLM 要求的每个函数
        for tool_call in msg.tool_calls:
            fn_name = tool_call.function.name
            fn_args = json.loads(tool_call.function.arguments)

            print(f"  → 调用: {fn_name}({fn_args})")
            result = FUNCTION_MAP[fn_name](**fn_args)
            print(f"  ← 结果: {result}")

            # ⑥ 把执行结果还给 LLM
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": json.dumps(result, ensure_ascii=False),
            })

        # ⑦ 第二次调用：LLM 基于函数结果组织自然语言回答
        final_response = client.chat.completions.create(
            model="qwen-plus",
            messages=messages,
        )
        answer = final_response.choices[0].message.content
    else:
        # LLM 判断不需要调函数，直接回答
        answer = msg.content

    print(f"\nAI: {answer}")
    return answer


# ⑧ 测试几个问题
chat_with_tools("2024-01-17 的订单量是多少？")
chat_with_tools("帮我查一下用户 U001 的信息")
chat_with_tools("你好，今天天气怎么样")  # 不触发工具调用
```

## 运行后你会看到什么

```
用户: 2024-01-17 的订单量是多少？

[LLM 决定调用工具]
  → 调用: get_order_count({'date': '2024-01-17'})
  ← 结果: {'date': '2024-01-17', 'count': 215}

AI: 2024-01-17 的订单量为 215 单。

[LLM 决定调用工具]
  → 调用: get_user_info({'user_id': 'U001'})
  ← 结果: {'name': '张三', 'level': 'VIP', 'orders': 42}

AI: 用户 U001 是张三，VIP 用户，历史订单共 42 单。

AI: 你好！抱歉，我没有查询天气的能力...
```

## 3 个核心概念

### 1. tools 定义（JSON Schema）

```python
{
    "name": "函数名",          # LLM 用这个名字决定调哪个
    "description": "描述",    # LLM 靠这个判断什么时候用
    "parameters": {...}       # LLM 靠这个知道传什么参数
}
```

`description` 写得越清楚，LLM 判断越准确。这是 Function Calling 效果的关键。

### 2. 两次 LLM 调用

```
第1次：让 LLM 决策 → 返回 tool_calls
执行函数
第2次：让 LLM 基于结果回答 → 返回自然语言
```

中间执行函数是你的代码，不是 LLM。

### 3. tool_choice

```python
tool_choice="auto"    # LLM 自己决定要不要调（最常用）
tool_choice="none"    # 禁止调工具
tool_choice={"type": "function", "function": {"name": "xxx"}}  # 强制调指定工具
```

## 和 RAG 的区别

| | RAG | Function Calling |
|---|---|---|
| 数据来源 | 预先存好的文档 | 实时调用函数/接口 |
| 适合场景 | 知识库问答、文档检索 | 查数据库、调 API、执行操作 |
| 实时性 | 数据是静态的 | 可以拿到最新数据 |

实际项目里两者经常一起用：
- 用 RAG 查产品文档
- 用 Function Calling 查用户订单

## 面试怎么说

> "Function Calling 是 LLM 和外部系统的桥梁。LLM 负责理解意图、决策调哪个函数、提取参数；真正的执行在应用层。这样 LLM 不需要直接连数据库或调接口，安全可控，也方便做权限验证。"
