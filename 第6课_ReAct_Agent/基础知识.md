# 第6课：ReAct Agent

## 这节课解决什么问题

第2课的 Function Calling，每次只调一个工具，调用流程是你写死的。但真实任务往往需要 LLM 自己决定：先调哪个工具、再调哪个、调几次。

```
用户："北京气温多少？100美元能换多少人民币？两个数字加起来是多少？"

普通做法（你写代码控制流程）：
  if "天气" in input: call weather_tool()
  if "汇率" in input: call exchange_tool()
  ...

ReAct Agent（LLM 自主规划）：
  Thought: 我需要先查天气，再查汇率，最后做加法
  Action: search_weather("北京")
  Observation: 22°C
  Thought: 现在查汇率
  Action: get_exchange_rate("USD")
  Observation: 7.25
  Thought: 22 + 725 = 747，我知道答案了
  Final Answer: 北京气温22°C，100美元=725人民币，两数相加是747
```

---

## ReAct 是什么

**ReAct = Reason + Act**，是一种让 LLM 交替"思考"和"行动"的模式：

```
Thought     → 分析当前状态，决定下一步
Action      → 调用工具
Observation → 得到工具结果
Thought     → 基于结果继续分析
...
Final Answer → 得出最终答案
```

这个循环由 LangChain 的 `AgentExecutor` 自动处理：
1. 把 LLM 输出解析成 Action
2. 执行对应工具
3. 把 Observation 追加到上下文
4. 重复，直到 LLM 输出 `Final Answer`

---

## 代码结构

### 1. 定义工具

用 `@tool` 装饰器把普通函数变成 Agent 可用的工具。函数的 docstring 是工具描述，LLM 靠它决定什么时候用这个工具。

```python
from langchain_core.tools import tool

@tool
def search_weather(city: str) -> str:
    """查询指定城市的今日天气，支持北京、上海、广州"""
    # docstring 是给 LLM 看的，要写清楚工具的作用和输入格式
    ...
```

### 2. 创建 Agent

```python
from langchain.agents import create_agent

# 直接传 llm 和 tools，框架自动处理循环（LangChain 1.x 新 API）
agent = create_agent(llm, tools)
```

### 3. 运行

```python
result = agent.invoke({"messages": [{"role": "user", "content": "你的问题"}]})
print(result["messages"][-1].content)  # 最终答案
```

---

## LangChain 1.x 的变化

旧版（0.x）需要手写 ReAct prompt 模板，解析器靠识别文本关键词（`Action` / `Final Answer`）驱动循环，容易因 LLM 输出格式不对而崩溃。

新版（1.x）的 `create_agent` 底层走 **工具调用协议**（tool_calls），LLM 直接返回结构化的工具调用指令，不再依赖文本解析，更稳定，也不需要手写 prompt 模板。

---

## Agent vs 普通 LLM 调用的区别

| | 普通调用 | ReAct Agent |
|---|---|---|
| 工具调用次数 | 你写死（1次或固定流程） | LLM 自主决定（动态） |
| 多步推理 | 需要你拆解任务 | LLM 自动拆解 |
| 代码复杂度 | 低 | 中（框架处理了循环） |
| Token 消耗 | 少 | 多（每轮 Observation 追加上下文） |
| 适合场景 | 流程固定的任务 | 流程不固定、需要自主判断的任务 |

## 面试怎么说

> "Agent 和普通 LLM 调用最大的区别是：Agent 能自主决定调用哪些工具、按什么顺序调、调几次。
>
> ReAct 是最常用的 Agent 框架，核心是一个 Thought→Action→Observation 的循环：LLM 分析情况、选工具、拿到结果、继续分析，直到能回答问题。
>
> 实现上用 LangChain 的 `create_agent`（底层走 LangGraph），框架自动处理循环、执行工具、把结果追加到上下文。
>
> 代价是 Token 消耗更多，因为每轮循环都会把之前所有的 Observation 带入下一轮。复杂任务可能要循环 5-10 轮，成本比单次调用高很多。"
