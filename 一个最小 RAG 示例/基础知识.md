# LangChain 基础学习：一个最小 RAG 示例

这份笔记不是逐行翻译代码，而是按“你已经有代码基础”的方式来讲：

1. 先看这段代码到底在解决什么问题
2. 再看 LangChain 里的核心组件分别负责什么
3. 最后看一版更适合初学者理解的整理代码

---

## 1. 这段代码在做什么

这其实是一个最基础的 **RAG（Retrieval-Augmented Generation，检索增强生成）** 示例。

它不是让大模型直接回答问题，而是：

1. 先读取本地文档
2. 把文档切成小块
3. 把小块转成向量，存入 Redis 向量库
4. 用户提问时，先去 Redis 里找最相关的内容
5. 再把“检索到的内容 + 用户问题”一起交给大模型回答

一句话理解：

> RAG = 先查资料，再让模型基于资料回答。

---

## 2. 原始代码整理版

下面是按学习用途整理过的一版。逻辑和你原来的代码一致，但我顺手修正了一个关键点：

- 向量库存储时应该优先存 `texts`，也就是切分后的文档块
- 不建议直接存原始 `documents`

```python
import os
from langchain.chat_models import init_chat_model
from langchain_community.document_loaders import Docx2txtLoader
from langchain_community.embeddings import DashScopeEmbeddings
from langchain_community.vectorstores import Redis
from langchain_classic.text_splitter import CharacterTextSplitter
from langchain_core.prompts import PromptTemplate
from langchain_core.runnables import RunnablePassthrough


# 1. 初始化聊天模型
llm = init_chat_model(
    model="qwen-plus",
    model_provider="openai",
    api_key=os.getenv("aliQwen-api"),
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
)


# 2. 定义 Prompt 模板
prompt_template = """
请使用以下提供的文本内容来回答问题。仅使用提供的文本信息，
如果文本中没有相关信息，请回答"抱歉，提供的文本中没有这个信息"。

文本内容：{context}
问题：{question}
回答：
"""

prompt = PromptTemplate(
    template=prompt_template,
    input_variables=["context", "question"],
)


# 3. 初始化 Embedding 模型
embeddings = DashScopeEmbeddings(
    model="text-embedding-v3",
    dashscope_api_key=os.getenv("aliQwen-api"),
)


# 4. 加载 Word 文档
loader = Docx2txtLoader("alibaba-java.docx")
documents = loader.load()


# 5. 文档切分
text_splitter = CharacterTextSplitter(
    chunk_size=1000,
    chunk_overlap=100,
)
texts = text_splitter.split_documents(documents)


# 6. 构建 Redis 向量库
vector_store = Redis.from_documents(
    documents=texts,
    embedding=embeddings,
    redis_url="redis://localhost:6379",
    index_name="my_index",
)


# 7. 创建检索器
retriever = vector_store.as_retriever(search_kwargs={"k": 2})


# 8. 把检索结果格式化为字符串
def format_docs(docs):
    return "\n\n".join(doc.page_content for doc in docs)


# 9. 组装 RAG Chain
rag_chain = (
    {
        "context": retriever | format_docs,
        "question": RunnablePassthrough(),
    }
    | prompt
    | llm
)


# 10. 发起提问
result = rag_chain.invoke("00000和A0001分别是什么意思")
print(result.content)
```

## 3. 你必须先理解的 6 个 LangChain 组件

### 3.1 `Loader`

这里用的是：

```python
loader = Docx2txtLoader("alibaba-java.docx")
documents = loader.load()
```

作用是把外部文件读成 LangChain 统一使用的 `Document` 对象。

你可以把 `Document` 理解成：

- `page_content`：正文
- `metadata`：附加信息，比如来源、页码、路径等

也就是说，`Loader` 解决的是“怎么把文件接进 LangChain”。

---

### 3.2 `TextSplitter`

这里用的是：

```python
texts = text_splitter.split_documents(documents)
```

为什么要切分？

因为整篇文档太长：

- 不适合直接做向量化
- 不适合直接检索
- 即使检索到了，返回的内容粒度也太粗

所以 RAG 一般都会先切块。

你可以这样理解：

- `documents` 是整篇资料
- `texts` 是切成很多小段之后的资料块

RAG 检索时，真正拿来比相似度的，通常是这些小段，而不是整篇文档。

---

### 3.3 `Embeddings`

这里用的是：

```python
embeddings = DashScopeEmbeddings(...)
```

Embedding 模型不负责回答问题，它负责把文本变成向量。

为什么要变成向量？

因为向量可以表达语义相似度。  
比如“请假制度”和“休假规则”虽然字面不同，但向量空间里可能很接近。

所以：

- 聊天模型：负责生成答案
- Embedding 模型：负责语义检索

这两个角色不要混。

---

### 3.4 `VectorStore`

这里用的是 Redis：

```python
vector_store = Redis.from_documents(...)
```

它做了两件事：

1. 调用 embedding 模型把文本块转成向量
2. 把向量和原文一起存到 Redis

所以 Redis 在这里不是普通缓存，而是 **向量数据库载体**。

你以后还会遇到：

- FAISS
- Chroma
- Milvus
- PGVector

本质都是一类东西：存向量并支持相似度检索。

---

### 3.5 `Retriever`

这里用的是：

```python
retriever = vector_store.as_retriever(search_kwargs={"k": 2})
```

它的作用是把“向量库”变成“可查询的检索器”。

意思就是：

- 用户给一个问题
- retriever 去向量库查相似内容
- 返回最相关的若干段文本

其中：

- `k=2` 表示返回最相关的 2 段

---

### 3.6 `Prompt + Chain + LLM`

这里是核心链路：

```python
rag_chain = (
    {
        "context": retriever | format_docs,
        "question": RunnablePassthrough(),
    }
    | prompt
    | llm
)
```

这段要重点看懂。

输入是一个问题，比如：

```python
"00000和A0001分别是什么意思"
```

这个输入会分成两路：

- 一路交给 `retriever`，查出相关资料，最后形成 `context`
- 一路原样透传，形成 `question`

然后：

1. `prompt` 把 `context` 和 `question` 拼成完整提示词
2. `llm` 根据这个提示词生成回答

其中：

```python
RunnablePassthrough()
```

就是“原样传递输入”的意思。

---

## 4. 这段代码的真实执行流程

当你执行：

```python
result = rag_chain.invoke("00000和A0001分别是什么意思")
```

底层流程大致是：

1. 把这个问题交给 `retriever`
2. `retriever` 用问题向量去 Redis 中搜索相似文本块
3. 返回最相关的 2 段文本
4. `format_docs()` 把这 2 段文本拼接成一个字符串
5. `prompt` 生成最终提示词
6. `llm` 基于提示词回答
7. `result.content` 输出答案

如果你把这个流程画成一条线，就是：

```text
用户问题
  -> 检索器
  -> 找到相关文档块
  -> 拼成上下文
  -> 填入 Prompt
  -> 调用大模型
  -> 输出答案
```

## 5. 你这份代码里最值得学的点

### 5.1 LangChain 的价值不是“替你调用模型”

直接调模型 API 你自己也能写。

LangChain 的价值在于，它把这些组件串起来：

- 文件加载
- 文本切分
- 向量化
- 检索
- Prompt 组装
- 模型调用

所以你学 LangChain，不是只学某个函数，而是学这种“工作流式拼装”。

---

### 5.2 RAG 的关键不是模型，而是检索质量

很多人会把重点放在模型上，其实 RAG 里经常更重要的是：

- 文档切分是否合理
- embedding 模型是否合适
- 检索返回的 `k` 是否合理
- prompt 是否限制模型只基于上下文回答

如果检索错了，模型再强也容易胡说。

---

### 5.3 文档切分后的 `texts` 比原始 `documents` 更适合入库

你原来代码里最明显的学习点就是这里：

```python
texts = text_splitter.split_documents(documents)
```

结果后面建库时用了：

```python
documents=documents
```

更合理的是：

```python
documents=texts
```

因为检索的最小单位应该是“文本块”。

---

## 6. 初学 LangChain 时你要建立的脑图

你可以先把 LangChain 基础记成这条链：

```text
文档 -> 切块 -> 向量化 -> 向量库 -> 检索 -> Prompt -> LLM -> 答案
```

如果这条链你能讲清楚，RAG 基础就已经入门了。

---

## 7. 这段代码还有哪些可以继续优化

如果后面你继续学，可以逐步加这些内容：

1. 把 `CharacterTextSplitter` 换成更适合中文/语义的切分方式
2. 给文档块加上更完整的 `metadata`
3. 调整 `k`、`chunk_size`、`chunk_overlap`
4. 增加“无答案兜底”逻辑
5. 把单次 `invoke()` 扩展成聊天式问答

这些都属于 RAG 的下一步，不是第一天必须掌握的内容。

---

## 8. 你现在应该记住什么

如果只记 4 句话，就记这 4 句：

1. LangChain 是用来串联 LLM 工作流的，不只是调模型。
2. RAG 的核心思想是“先检索，再生成”。
3. 向量库里通常存的是切分后的文本块，不是整篇文档。
4. `retriever | prompt | llm` 这条链，就是最基础的 LangChain 思路。

---

## 9. 下一步怎么学

建议你下一步按这个顺序练：

1. 自己把这段代码手敲一遍
2. 把 `Docx2txtLoader` 换成 txt 或 pdf 文档试一次
3. 改 `k=2`、`chunk_size=1000` 看效果差异
4. 自己打印检索出的 `docs`，观察 RAG 到底检索到了什么

最关键的一步不是跑通，而是：

> 你要能看见“检索出来的上下文”到底是什么。

因为 RAG 是否靠谱，很多时候就输赢在这里。
